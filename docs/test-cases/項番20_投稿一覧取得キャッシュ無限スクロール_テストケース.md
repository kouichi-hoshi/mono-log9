# 項番20 テストケース

## 対象

- 投稿一覧の取得（通常/ごみ箱）
- TanStack Query によるキャッシュ分離（`view` + `favoriteOnly`）
- cursor 方式の無限スクロール
- 初回/追加読み込みのローディング出し分け
- エラー時の再試行導線
- 一覧条件単位のスクロール位置保存/復元

## 非対象

- お気に入り操作の本実装（項番21）
- hasEdits 離脱確認（項番22）
- ごみ箱の一括完全削除（項番23）

| ID | レベル(Unit\|結合\|E2E) | 観点 | 前提 | 手順 | 期待結果 | 実績(Pass/Fail) | メモ | 証跡 |
|---|---|---|---|---|---|---|---|---|
| TC-001 | Unit | 一覧条件導出: `view=trash` は `favoriteOnly=false` 固定 | 一覧条件導出関数が利用可能 | `view=trash` かつ `favoriteNote=true` を入力して一覧条件を導出する | 導出結果の `favoriteOnly` が `false` になる |  |  |  |
| TC-002 | Unit | queryKey 分離（`view` 差分） | queryKey 生成関数が利用可能 | `view=memo,favoriteOnly=false` と `view=note,favoriteOnly=false` で key を生成する | 2つの key が一致しない |  |  |  |
| TC-003 | Unit | queryKey 分離（`favoriteOnly` 差分） | queryKey 生成関数が利用可能 | `view=memo,favoriteOnly=false` と `view=memo,favoriteOnly=true` で key を生成する | 2つの key が一致しない |  |  |  |
| TC-004 | Unit | `cursor` を queryKey に含めない | queryKey 生成関数が利用可能 | 同一 `view/favoriteOnly` で `cursor` だけ変えて key を生成する | key は同一になる |  |  |  |
| TC-005 | Unit | `getNextPageParam` 契約 | `ListPostsResult` 相当を組み立て可能 | `nextCursor='c2'` と `nextCursor=null` の2パターンで `getNextPageParam` を実行する | 前者は `'c2'`、後者は `undefined` を返す |  |  |  |
| TC-006 | Unit | 多重発火防止ガード | sentinel 判定ロジックが利用可能 | `hasNextPage=true` で `isFetchingNextPage=true` を与える | `fetchNextPage` が呼ばれない |  |  |  |
| TC-007 | Unit | 復元中ガード | sentinel 判定ロジックが利用可能 | `hasNextPage=true` で `isRestoringScroll=true` を与える | `fetchNextPage` が呼ばれない |  |  |  |
| TC-008 | Unit | スクロール保存キーの単位 | スクロールキー生成関数が利用可能 | `view=memo,favoriteOnly=false` と `view=memo,favoriteOnly=true` でキー生成する | キーが異なり、一覧条件単位で分離される |  |  |  |
| TC-009 | 結合 | 初回読み込み（データ未取得） | `listPostsAction` を遅延成功モックできる | 画面表示直後の UI を確認し、初回取得完了を待つ | 取得完了前は全体スケルトン表示、完了後は一覧表示に切り替わる |  |  |  |
| TC-010 | 結合 | 追加読み込み時の表示 | 初回ページ取得済みかつ `hasNext=true` | 末尾 sentinel を交差させて追加取得を発火する | 既存一覧を維持したまま末尾ローディングのみ表示される |  |  |  |
| TC-011 | 結合 | 終端時の追加取得停止 | 最終ページ取得済み（`hasNext=false`） | 末尾 sentinel を交差させる | 追加取得が発火しない |  |  |  |
| TC-012 | 結合 | 初回取得失敗時の再試行 | 初回 `listPostsAction` を失敗モックできる | 画面表示し、エラー表示後に「再試行」を押す | エラーが明示表示され、再試行で再取得が実行される |  |  |  |
| TC-013 | 結合 | 追加取得失敗時の再試行 | 初回成功、2ページ目のみ失敗するモックを用意 | sentinel で追加取得を発火し失敗させ、再試行導線を実行する | 既存一覧は維持され、再試行で `fetchNextPage` が再実行される |  |  |  |
| TC-014 | 結合 | 一覧条件切替時のキャッシュ即時復元 | memo と note の1ページ目を事前取得済み | `view=memo` から `view=note` に切替後、再度 `view=memo` に戻す | 取得済みの memo 一覧が即時表示される |  |  |  |
| TC-015 | 結合 | 画面切替時のちらつき防止 | memo と note の表示データが異なる | memo 表示中に note へ切替し、切替直後の DOM を確認する | note 切替直後に memo データが一瞬表示されない |  |  |  |
| TC-016 | 結合 | `NOT_IMPLEMENTED` の表示 | 初回取得で `NOT_IMPLEMENTED` エラーを返すモック | 画面表示してエラー表示を確認する | 空表示に置換されず、エラー文言が明示表示される |  |  |  |
| TC-017 | E2E | 無限スクロールの連続取得 | 2ページ以上のスタブデータが存在する | 画面下端までスクロールを繰り返す | ページが順次追加され、終端到達後は追加されない |  |  |  |
| TC-018 | E2E | 戻る/進むで状態復元 | `view` 切替操作が可能 | `view=memo` → `view=note` に切替後、ブラウザ戻る/進むを実行する | URL と一覧表示が履歴どおり復元される |  |  |  |
| TC-019 | E2E | `view=trash` で favorite 非評価 | favorite クエリ付き URL に遷移可能 | `?view=trash&favoriteMemo` で画面表示する | ごみ箱一覧が favorite 条件なしで表示される |  |  |  |
| TC-020 | E2E | favorite 状態のモード別保持 | memo/note 両モードで favorite 絞り込み切替が可能 | memo で favorite ON、note へ切替して favorite ON、再度 memo へ戻る | 各モードの favorite 状態が独立して保持される |  |  |  |
