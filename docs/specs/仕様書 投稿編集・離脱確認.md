# 概要

投稿編集（メモ/ノート）の表示、保存、離脱確認（hasEdits）の詳細仕様を定義する。

- TipTap の入力仕様は `docs/specs/仕様書 Tiptap.md` を正とする
- 投稿本文の保存形式/バリデーションは `docs/specs/仕様書 投稿編集-本文形式.md` を正とする
- URLクエリの共通仕様は `docs/specs/仕様書 URLクエリ状態管理.md` を正とする
- 離脱確認の表示文言は `docs/specs/テキスト・コンテンツ定義.md` を正とする

---

# エディタ仕様

- エディタはメモ用、ノート用の2つのコンポーネントで分けて実装する
- 保存されたメモとノートは互換性を持たない
- 投稿のモードは変更できない（編集時も固定）

## メモエディタ

- inputフィールド
  - 一行テキスト（短文）を入力する想定のinputフィールドを設置する
  - 入力されたURLは、保存後の投稿カード表示時に a 要素としてレンダリングする（target="_blank" rel="noopener noreferrer"）。
  - リンク化対象は URL 本体のみとし、末尾の句読点や括弧などの記号（例: `。` `、` `.` `,` `!` `?` `)` `]` `}`）はリンクに含めない。URL 前後の空白はリンク外の通常テキストとして扱う。
  - 保存データ自体は変更しない。
- 「保存する」ボタン
  - 押下するとメモが保存される

## ノートエディタ

- タイトル入力エリア
  - 未入力可
  - バリデーション内容は別途定義
- テキスト入力エリア
  - 長文を入力する想定のリッチテキストエディタ（TipTap）を設置する
  - マークダウン風ショートカット入力を許可する
  - ツールバー装飾（見出し/リスト/引用/太字/リンク）を許可する
  - 保存可否（許可ノード/マーク）は `docs/specs/仕様書 投稿編集-本文形式.md` を正とする
- 「保存する」ボタン
  - 押下するとノートが保存される

## メモ・ノート共通の保存仕様

- 保存時は現在アクティブな表示モードに対応した投稿モードで保存する
- 押下すると投稿内容、モード、日時が保存される
- 保存完了後は以下の状態にする
  - エディタ入力内容をクリアする
  - 再びエディタにフォーカスを当てる
- 本文が未入力（空白のみ含む）の場合は保存せず、toastで通知する
- 本文の最大文字数を超える場合は保存せず、toastで通知する
  - メモ: 最大 全角140文字 / 半角280文字
  - ノート: 最大 全角25,000文字

# hasEdits（離脱確認）仕様

## 定義

- `hasEdits` は、編集開始時点の内容に対して未保存の変更があるかを示すフラグ

## 判定ルール

- `hasEdits=true` になる条件
  - 編集開始時点の内容から、タイトル/本文などが変更されたとき
- `hasEdits=false` になる条件
  - 編集開始直後（初期値読み込み直後）
  - 現在値が編集開始時点の値と一致しているとき（途中で戻した場合を含む）
  - 保存成功後（保存結果を新しい基準値に更新した時点）
  - 「破棄して続行」を確定して編集状態を終了したとき

## 比較基準（実装基準）

- メモ本文
  - 編集開始時点の値と現在値を文字列で比較する
- ノートタイトル
  - trim後の値で比較する
- ノート本文
  - TipTap JSONで比較する
  - `null` と空の `doc`（`{ type: "doc", content: [] }`）は同値として扱う
- 保存成功時
  - 保存後の値を新しい基準値として更新する

## 離脱確認の起動条件

- キャンセルボタン押下時
  - `hasEdits=false`: 通常の一覧表示へ戻る
  - `hasEdits=true`: クローズ確認ダイアログを起動する
- Esc押下時
  - `hasEdits=false`: 通常の一覧表示へ戻る
  - `hasEdits=true`: クローズ確認ダイアログを起動する
- ノートモーダルのクローズ要求（キャンセル / Esc / 背景クリック）
  - `hasEdits=false`: 通常の一覧表示へ戻る
  - `hasEdits=true`: クローズ確認ダイアログを起動する
- その他の起動条件
  - モード切替 / お気に入り絞り込み / ごみ箱表示切替など、URLパラメータが変わる操作
  - 他の投稿の編集開始操作
  - ブラウザの戻る/進むでURL変更が発生する場合

## モード切替即時反映との優先順位

- `hasEdits=true` の間は、モード切替ボタン押下時に見た目の即時切替を行わない
- まず離脱確認ダイアログを表示し、選択結果に応じて遷移可否を確定する
- 「編集を続ける」選択時は、見た目・URLともに変更しない
- 「破棄して続行」選択時のみ、モード切替処理を実行する

## 離脱確認ダイアログの選択肢

- 「破棄して続行」
  - 編集を破棄して保留中の操作を実行する
- 「編集を続ける」
  - 保留中の操作をキャンセルし、編集状態を維持する

## 戻る/進む時の挙動

- 戻る/進むで発生した遷移先は、離脱確認が確定するまで保留する
- 保留中は遷移先UIを一瞬でも表示しない（ちらつかせない）
- 「編集を続ける」選択時は保留遷移を破棄し、編集状態を維持する
- 「破棄して続行」選択時は編集状態を破棄し、保留遷移を適用する

# エディタの出し分け仕様

- URLクエリ `view` から画面状態を判定する
- `view=memo`
  - 投稿モードは `mode=memo`
  - メモエディタを表示する
- `view=note`
  - 投稿モードは `mode=note`
  - ノートエディタはモーダル内に配置する（初期非表示）
  - 「ノートを書く」ボタン押下でモーダルを開く
- `view=trash`
  - エディタを表示しない

## 項番22-A（ノートモーダル履歴連動）補足

- 項番22-Aで、ノートモーダル状態を `noteComposer` クエリで管理する
  - `create` / `edit:<postId>` を用いる
- 開く操作は履歴を1件積み、閉じる操作はクエリ差分で反映する
- 詳細なクエリ正規化/保持ルールは `docs/specs/仕様書 URLクエリ状態管理.md` を正とする
