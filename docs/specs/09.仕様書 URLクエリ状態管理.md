# 概要

ログイン中画面の表示状態を URL クエリで一元管理し、以下を実現する。

- モード切替・ごみ箱表示・お気に入り絞り込み状態を URL から復元できる
- ブラウザの戻る/進むで状態が再現される
- ログイン中画面で `view/favorite` を更新するとき、他クエリ（例: `stubAuth`）を破壊しない

---

# クエリパラメータ仕様

対象画面: ログイン中画面（`AuthedScreen`）

| パラメータ          | 値                           | デフォルト  | 用途             |
| -------------- | --------------------------- | ------ | -------------- |
| `view`         | `memo` \| `note` \| `trash` | `memo` | 表示中の画面状態       |
| `favoriteMemo` | パラメータ有り/無し                  | 無し     | お気に入り絞り込み（メモ）  |
| `favoriteNote` | パラメータ有り/無し                  | 無し     | お気に入り絞り込み（ノート） |
| `noteComposer` | `create` \| `edit:<postId>` | 無し     | ノートモーダル状態（項番22-Aで導入） |

- 実URLでは `?favoriteMemo` または `?favoriteMemo=` のどちらも「有り」とみなす。
- `favoriteMemo` / `favoriteNote` は有無で判定し、未指定は OFF とみなす
- favorite はモード別で持つ
- `noteComposer` は項番22-Aで導入する。項番21の時点では未使用（クエリ未付与）とする

## 用語と責務の分離

- `view` は画面状態を表す URL パラメータ（`memo` / `note` / `trash`）
- `mode` は投稿データの種別（`memo` / `note`）を表す内部値であり、URL パラメータではない
- 画面で利用する投稿種別は、`view` から導出した `activeMode` を使って判定する
	- `view=memo` のとき `activeMode=memo`
	- `view=note` のとき `activeMode=note`
	- `view=trash` のとき `activeMode=null`
- `view` から `activeMode` を導出する判定ロジックは 1 箇所に集約する

## クエリ保持ルール

- `view/favoriteMemo/favoriteNote` を更新するとき、他クエリは保持する
	- 例: `stubAuth=1` は失わない
- 項番22-A導入後は、`noteComposer` を更新するときも他クエリを保持する
- 未知のクエリキーも削除しない
- `view` が不正値・未知値・欠落の場合は `memo` へフォールバックする
- 同一キーの重複は正規化し、1キー分の有無として扱う
	- `view` が重複する場合は、URL上で最初に出現した値を優先する（先勝ち）
	- `view` の先頭値が不正（`memo` / `note` / `trash` 以外）の場合は `memo` へ補正する
	- `noteComposer` の値が不正な場合は未指定（無し）に補正する

補正後の例:

- `/?stubAuth=1`
  → `/?stubAuth=1&view=memo`
- `/?stubAuth=1&view=xxx&favoriteMemo&favoriteMemo`
  → `/?stubAuth=1&view=memo&favoriteMemo`
- `/?view=note&view=memo&favoriteNote&favoriteNote`
  → `/?view=note&favoriteNote`

## 履歴ルール

- ユーザー操作による状態変更は履歴を積む（戻る/進む可能）
- 項番22-A導入後は、ノートモーダルを開く操作（`noteComposer` 付与）で履歴を1件積む
- 項番22-A導入後は、ノートモーダルを閉じる操作で `noteComposer` を除去する
- 初期正規化（不足/不正の補正）は、画面初期表示時にクエリを正規形へ補正する処理を指す
	- 対象: `view` の欠落/不正/重複、`favoriteMemo` / `favoriteNote` の重複
	- 補正は履歴を追加しない方法（`replace` 相当）で行う
- URLが実質変化しない操作は履歴を増やさない
- 項番21の hasEdits 導入後は、編集中（`hasEdits=true`）に戻る/進むで発生した遷移は確認完了まで保留する
	- 「編集を続ける」選択時は保留遷移を破棄する
	- 「破棄して続行」選択時は保留遷移を適用する

## ごみ箱表示時の評価ルール

- `view=trash` のときは `favoriteMemo` / `favoriteNote` を保持していても評価しない
- `view=trash` から `view=memo` / `view=note` へ戻ったときは、保持していた favorite クエリの状態を再び評価する

## ログアウト時の扱い（補足）

- 本仕様の「他クエリ保持」はログイン中画面での `view/favorite` 更新時にのみ適用する
- ログアウト時は `docs/specs/02.仕様書 機能.md` と `docs/specs/07.仕様書 スタブ認証（URLトグル）.md` を正とし、URL パラメータを全削除して `/` へ戻す

## 実装スコープ補足（項番15/21/22-A）

- 項番15（URLクエリ状態管理）では、URL更新・正規化・履歴制御までを対象とする
- 項番21では、hasEdits の離脱確認ダイアログとURL変更時の保留/継続/破棄制御を導入する
- 項番22-Aで、`noteComposer` によるノートモーダル履歴連動を導入する
