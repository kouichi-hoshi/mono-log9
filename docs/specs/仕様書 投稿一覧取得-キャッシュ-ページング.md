# 目的

- 投稿一覧の取得/キャッシュ/無限スクロールの仕様を固定する
- モード切替・ごみ箱切替・戻る/進む時の体感性能（即時復元）を担保する
- 初回読み込みと追加読み込みでローディングUIの責務を分離し、ちらつきを防ぐ

# スコープ

- 対象
  - 投稿一覧の読み取り（通常一覧/ごみ箱一覧）
  - 一覧条件単位のキャッシュ方針
  - cursor 方式の無限スクロール仕様
  - 初回/追加読み込み時のローディング表示
  - 一覧単位のスクロール位置保存/復元
- 非対象
  - 投稿作成/更新/ごみ箱投入/復元/完全削除の本実装（項番18/19/23）
  - お気に入り操作本実装（項番22）
  - hasEdits 離脱確認（項番21）

# 用語

- `view`: 画面状態（`memo` / `note` / `trash`）。URLクエリで管理する
- `favoriteOnly`: お気に入り絞り込み有無（boolean）
- `view=trash` のときは常に `false` として扱う（favorite クエリは非評価）
- 一覧条件: `view` と `favoriteOnly` の組み合わせ
- ページング契約: `items` / `hasNext` / `nextCursor`
- cursor token: 詳細契約は `docs/specs/仕様書 Cursorページングトークン.md` を正とする

# 機能仕様

## 一覧取得契約

- 一覧取得は、一覧条件（`view` と `favoriteOnly`）およびページング条件（`limit` と `cursor`）を入力として実行する
- 入力:
  - `view` は `memo` / `note` / `trash` のいずれか
  - `favoriteOnly` は真偽値で指定する
  - `limit` は1回の取得件数を指定する（初期値は `10`、許容範囲は `1..50`）
  - `cursor` は次ページ取得時のみ指定する
- 出力:
  - `items`（投稿配列）
  - `hasNext`（次ページ有無）
  - `nextCursor`（次ページ取得トークン）
- `nextCursor` は終端時 `null`
- cursor 契約（`v1` 形式、検証、継続条件、`INVALID_CURSOR` 判定）は `docs/specs/仕様書 Cursorページングトークン.md` を正とする
- 不正 `limit`（非整数、0以下、51以上）は `VALIDATION_ERROR` を返す

## キャッシュ仕様

- 再検証を抑制し、一覧条件切替時の即時復元を優先する
- 一覧条件単位でキャッシュを分離する
- モード切替/ごみ箱切替/戻る進むで、同一一覧条件の取得済みデータを即時復元する
- お気に入り絞り込みON/OFF時は、遷移先の一覧条件が未取得の場合のみ初回取得を行う
- お気に入り絞り込みON/OFF時に、遷移先の一覧条件が取得済みの場合はキャッシュを即時復元し、切替操作自体では強制再取得しない
- `view=trash` では favorite を評価しない
- キャッシュ有効期間や再取得条件の具体パラメータは `docs/designs/投稿一覧取得-キャッシュ-ページング_設計.md` を正とする

## 無限スクロール仕様

- 末尾 sentinel が表示領域に入ったら次ページ取得を開始する
- 多重発火防止を行う
- `hasNext=false` になったら追加取得を停止する
- 追加取得は `nextCursor` 契約に従う

## ローディング表示仕様

- 初回読み込み（その一覧条件のデータ未取得）:
  - スケルトンを表示する
  - 一覧データは表示しない
- 追加読み込み（`isFetchingNextPage`）:
  - 取得済み一覧は維持する
  - 末尾に追加ロード用スケルトンを表示する
- 背景再取得（既存データあり）:
  - スケルトンは表示しない
- 画面切替時:
  - 前の一覧条件のデータを一時表示しない
  - 現在の一覧条件に一致するデータのみ描画する

## エラー/再試行仕様

- 初回取得失敗:
  - エラー文言を明示する
  - 再試行導線（`refetch`）を表示する
- 追加取得失敗:
  - 取得済み一覧は維持する
  - エラー通知（トースト）と再試行導線（`fetchNextPage`）を表示する
- `NOT_IMPLEMENTED` は空表示に置き換えず、画面上に明示する

## スクロール位置仕様

- 保存単位は次の2種類を併用する
  - 一覧条件単位（`view` + `favoriteOnly`）
  - 履歴エントリ単位（ブラウザの戻る/進むで移動する履歴位置）
- 保存先は `sessionStorage`（タブ単位）
- 保存タイミング:
  - URL更新直前
  - 画面離脱時（cleanup）
- 復元タイミング:
  - 該当一覧条件のデータ描画後
  - レイアウト確定後に `scrollTo` で復元する
- 復元時の優先順位:
  - 履歴エントリ単位の保存値を優先する
  - 履歴エントリ単位の保存値がない場合は一覧条件単位の保存値を使う
- 戻る/進む遷移中に、未スクロール状態（`0`）で既存の保存値を上書きしない
- 復元処理中は、復元直後の連続追加取得が発生しないように制御する

## 更新系操作時の整合仕様

- 投稿更新/お気に入り脱着/ごみ箱投入/復元は、一覧表示中の整合維持のためキャッシュ更新を行う
- 差分更新を優先し、差分で整合が取れない場合のみ再取得する
- お気に入り脱着は、同一 `view` の関連一覧キー（`favoriteOnly=true/false` の両方）を整合更新対象とする
- 関連一覧キーを差分更新できない場合は、関連一覧キーを `invalidate` して整合を担保する
- ごみ箱関連操作は通常一覧キーとごみ箱一覧キーの両方を対象に整合を取る

# 詳細設計

- 実装手段・クエリキー具体形・ローダー制御・スクロール復元アルゴリズムは `docs/designs/投稿一覧取得-キャッシュ-ページング_設計.md` を正とする

# 受け入れ条件（項番20）

- 一覧条件単位でキャッシュが分離され、切替時に取得済みデータを即時復元できる
- キャッシュ方針が `staleTime=5分 / gcTime=30分 / refetchOnMount/WindowFocus/Reconnect=false` を満たす
- cursor 方式で無限スクロールできる（`nextCursor` 契約に従う）
- 初回/追加読み込みでローディング表示を出し分けできる
- 画面切替時に前画面データのちらつきが発生しない
- 取得失敗時に一覧維持（追加取得失敗時）と再試行導線を提供できる
- スクロール位置を変更し、モード切替を繰り返した後に戻る/進むを複数回実行しても、対応する履歴位置のスクロールが復元される
