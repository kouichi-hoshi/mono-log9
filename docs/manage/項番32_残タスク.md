## 実認証E2E運用方針（項番32）

- 方針: 「アプリ内品質は自動化」「Google OAuth 画面遷移は手動スモーク」で運用する
- 自動化対象:
  - stub主要フロー、ログアウト後戻る/進む、BFCache観点
  - 実DB安全ガードと real project の未ログインスモーク
- 手動スモーク対象:
  - Google のアカウント選択/同意画面を実際に操作するフロー
  - T32-05〜T32-08 は Playwright ではなく通常ブラウザで検証し、証跡を記録する
- 実DB E2Eの安全実行前提:
  - `RUN_REAL_E2E=true` と `ALLOW_DB_WRITE_FOR_TESTS=true` を同時に指定する
  - `TEST_DB_HOST_ALLOWLIST` / `TEST_DB_NAME_ALLOWLIST` にテストDB接続先を明示し、許可外DBへの接続は fail-fast で停止する

## 実行環境の現状

| 項目 | 現状 |
|------|------|
| 実行コマンド | `mono-log9-app` で `pnpm test:e2e`（stub一括）、`pnpm test:e2e:real`（real自動スモーク） |
| 実DB E2Eガード | `RUN_REAL_E2E` + `ALLOW_DB_WRITE_FOR_TESTS` + allowlist 指定が必須（未指定時は開始前停止） |
| `playwright.config.ts` | 通常は `NEXT_DIST_DIR=.next-playwright PORT=3100 USE_STUB_AUTH=true USE_STUB_POSTS=true pnpm dev`。`RUN_REAL_E2E=true` 時のみ実認証向け設定へ切替 |
| `projects` | 通常は `chromium`。`RUN_REAL_E2E=true` 時は `real-chromium` を追加 |
| 実DB/実認証での Playwright | real project + globalSetup ガードを実装済み。`major-flow.real.spec.ts` は未ログインスモークのみを対象化 |

項番32の本番相当確認（T32-05〜T32-08）は、Playwright対象外として通常ブラウザ手動で実施し、証跡を記録する。
