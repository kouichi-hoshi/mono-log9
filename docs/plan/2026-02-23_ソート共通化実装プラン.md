# ソート共通化実装プラン（投稿一覧の並び安定化）

## Summary

- 目的は「投稿追加直後の並び」と「リロード後の並び」を一致させること。
- 方針は、表示用日時文字列（`YYYY-MM-DD HH:mm`）とソート用キーを分離し、クライアント・サーバーで同じ並び契約を使うこと。
- 追加で、決定済み方針として「旧スタブ cursor 互換を削除」する。

## 重要な API / 型変更

1. `PostRecord` にソート専用キーを追加する  
   対象: `/Users/kouichi/project/my_project/mono-log/mono-log9/mono-log9-app/lib/posts/types.ts`
   - `createdAtEpochMs?: number`
   - `trashedAtEpochMs?: number`
   - 既存の `createdAt` / `trashedAt`（表示用）は維持する

2. サーバー返却契約の更新
   - DB Repository は `createdAtEpochMs` と `trashedAtEpochMs` を必ず埋めて返す
   - Stub Repository も同様に埋める（既存表示文字列からパースして補完）

3. cursor 契約の整理（互換削除）
   - `legacy(post-xxx/trash-xxx)` 形式は受け付けない仕様に統一
   - `base64url(JSON)` の `v1` のみ許可

## 実装ステップ

1. 共通ソートユーティリティを新設  
   対象: `/Users/kouichi/project/my_project/mono-log/mono-log9/mono-log9-app/lib/posts/sort.ts`
   - `comparePostsByCreatedAtDesc(a, b)`
   - `comparePostsByTrashedAtDesc(a, b)`
   - 優先キーは `*EpochMs`。未設定時のみ表示文字列から安全にパースして比較
   - 最終 tie-break は `id DESC`

2. `AuthedScreen` のローカル comparator を共通化  
   対象: `/Users/kouichi/project/my_project/mono-log/mono-log9/mono-log9-app/components/authed/AuthedScreen.tsx`
   - 既存の `sortByCreatedAtDesc` / `sortByTrashedAtDesc` を削除
   - 新設 `sort.ts` を使うよう置換
   - `upsertForCurrentView`、ごみ箱移動時、復元時の sort 呼び出しを全置換

3. DB Repository の返却値にソートキーを追加  
   対象: `/Users/kouichi/project/my_project/mono-log/mono-log9/mono-log9-app/lib/posts/repositories/dbPostRepository.ts`
   - `toPostRecord` で `createdAtEpochMs: row.createdAt.getTime()` を付与
   - `trashedAt` がある場合は `trashedAtEpochMs` も付与

4. Stub Repository でも同じキーを返す  
   対象: `/Users/kouichi/project/my_project/mono-log/mono-log9/mono-log9-app/lib/posts/repositories/stubPostRepository.ts`
   - `createdAt` / `trashedAt` 文字列を epoch ms に変換するヘルパーを追加
   - create/move/restore/list の返却に `*EpochMs` を反映

5. cursor 互換削除を実装  
   対象: `/Users/kouichi/project/my_project/mono-log/mono-log9/mono-log9-app/lib/posts/cursor.ts`
   - `LEGACY_ID_PATTERN` と `kind: "legacy"` を削除
   - `parseCursorInput` は `undefined` または `v1` のみ
   - DB Repository の `listPosts` から legacy 分岐を削除し `v1` のみ処理

6. 仕様・設計ドキュメント更新
   - `/Users/kouichi/project/my_project/mono-log/mono-log9/docs/specs/15.仕様書 PrismaDB設計.md` の移行互換記述を削除
   - `/Users/kouichi/project/my_project/mono-log/mono-log9/docs/designs/PrismaDB設計_設計.md` の cursor 互換記述を削除
   - 必要に応じて `PostRecord` のソート用内部キーを追記

## テストケースとシナリオ

1. `sort.ts` 単体テスト
   - 同一 `createdAt` 表示（分同値）でも `createdAtEpochMs` 差で新規投稿が先頭
   - `trashedAtEpochMs` でも同様に降順安定
   - `EpochMs` 不在時は文字列パース fallback で比較可能

2. `AuthedScreen` 結合テスト
   - 投稿追加直後にローカルキャッシュ更新しても並びが仕様どおり（新しい順）
   - ごみ箱移動/復元後も期待順序を維持

3. cursor テスト
   - `post-001` 等の legacy cursor は `INVALID_CURSOR`
   - `v1` cursor は有効
   - 不正 token は `INVALID_CURSOR`

4. 既存回帰テスト
   - `postActions`、`stubPostRepository`、`AuthedScreen` の既存主要テスト再実行

## 受け入れ条件

- 投稿追加直後の一覧順とリロード後の一覧順が一致する
- UI の表示フォーマット `YYYY-MM-DD HH:mm` は変更しない
- cursor は `v1` のみ受け入れる
- 既存テスト群 + 新規テストがすべて成功する

## Assumptions / Defaults

- 採用方式は「比較キー追加（Recommended）」で確定
- `PostRecord` の新規キーは後方互換のため `optional` で導入し、Repository 返却では常に設定
- DB スキーマ変更は不要（レスポンス構造の拡張のみ）
- 旧スタブ cursor 互換は削除する
