# F7-8 パフォーマンス計測ベースラインと改善検証

- 現状実装をベースラインとして再レンダリング回数と主要操作応答を計測し、重さの原因箇所を特定する。

### 計測手順

1. 計測対象画面を開く。
2. 現状実装で各シナリオを 3 回計測し、Baseline を記録する。
3. Profiler の `What caused this update?` と render 内訳で原因候補を絞る。
4. 改善候補を1件実施し、同一条件で再計測する。
5. 差分を算出し、次の改善候補の優先度を更新する。

## 原因候補の絞り込み

| ID | 事象 | 根拠（Profiler/ログ） | 想定原因 | 優先度（High/Medium/Low） |
| --- | --- | --- | --- | --- |
| CAUSE-01 | モード切替時のrender時間が高め | 3回の1 commit目が40.4/52.0/57.4ms | モード切替に伴う描画範囲が広く、1 commitの負荷が高い | High |
| CAUSE-02 | ルーティング起因の更新が毎回発生 | `What caused this update?` が `AuthedScreen` + `Router` | URL状態更新に連動して `AuthedScreen` 配下が広く再評価される | High |
| CAUSE-03 | モーダル開閉でcommit数が多い | PERF-02 の各Runで `1/14`（=14 commits） | モーダル開閉時に再描画連鎖が発生し、更新回数が増えている | High |
| CAUSE-04 | 一覧操作の処理時間とcommit数のばらつきが大きい | PERF-03 の1 commit目が43.1〜56.7ms、commit数が7〜11 | キャッシュ状態や再評価対象の差で処理コストが不安定 | Medium |

## 分析メモ

- 主要な改善点: 未実施（現状把握フェーズ）
- 悪化/横ばいの観点: PERF-01/02/03 すべて 1 commit目が 40ms超で、体感遅延につながる可能性がある
- 想定要因: ルーター更新時に `AuthedScreen` 直下の再描画範囲が広く、モーダル開閉や一覧操作で更新回数が増えている
